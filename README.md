# 三国行纪 项目规划

战斗桌面现使用铜镜龙纹背景、竖式武将名签和独立民兵立绘。选牌后，悬停合法目标显示金框，点选后显示红框和出牌对象。右键手牌展开详情，左键收起，侧栏分列公开记录和关键战况。[战斗界面与鼠标操作](docs/12-新版PC鼠标交互核对.md)

以《三国杀Online》武将与卡牌规则为基础的三国背景策略单机游戏。玩家从平民出发，自由招募武将，通过武将卡牌战斗攻城略地，选择三种背景之一，经历各自从无名小辈到统一天下的完整故事。《三国行纪》为暂定工作名。

当前阶段：M0/G0进行中，已建立C#工程、内容校验、固定随机流、可保存恢复的抽牌试验，三线全程故事大纲已形成制作草稿。战斗开发核心已支持八种牌（拆顺仅手牌区）、关羽武圣、曹操奸雄及原创奋击I阶开发配置；可执行连续反无懈、暗牌选择、转换牌、多点伤害、濒死救援、伤后技能询问与终局，并在每个决策点保存恢复。Godot现已接入玩家对AI的战斗原型，支持选牌、目标与技能成本预览、确认取消及战斗存档备份恢复，并接入已采集的关羽、曹操立绘和OL武将框、八种卡面及按钮部件供内部开发验证；OL视觉还原、完整P0与G0全部验收仍待完成。实际进度见[开发进度](docs/06-开发进度.md)。

战斗桌面现支持双方各1至4人的全部16种配置：点击“新局”设置人数后开始；当前操作友军位于右下，其余角色沿周边显示。鼠标点手牌、点目标并确定，不再提供动作方案列表。武圣先点技能再点红牌；奋击先点技能、杀、额外弃牌和目标。手牌按单行横向滚动排列，显示花色点数、牌名、禁用灰置与选中标记；右键可查看用途，确认取消固定在底栏。“战斗记录”可查看公开出牌、响应、伤害、救援与终局；摸牌和顺走暗牌只记数量。不同人数使用独立存档槽，默认2对2的旧槽位保持不变。当前布局为开发映射，尚未完成OL同版本参照验收；素材仅用于内部验证包。

中央结算区显示公开卡面、来源与目标及反制层数，底栏保留最近的伤害、回复和技能提示。“武将资料”可查看所有角色的体力、手牌数量、完整技能及未启用原因；查看资料或战斗记录时暂停敌方推进，关闭后继续。以鼠标点选和拖放为主要操作；本次main整合保留已有Tab、Enter和空格查看与操作通路。无懈无合法牌时自动略过；有牌时点牌确定，或点“不出”“本次锦囊不再询问”。拆顺点击弹层中的牌背直接选取，不显示暗牌槽位按钮。桌面已改为竖式角色框、底部手牌与装备判定空态、右侧记录；目标为当前OL PC新版，尚未完成新版截图/录像对照，不能据此宣称已还原。读档不重播历史结算。

2026-11-17界面以用户补充的单将身份局截图为主参照：上方三席、左右各两席、右下操作武将、底部手牌与四格装备空态、右侧可收起信息栏。桌面使用项目自绘铜色刻纹，不使用首张截图的自定义草地背景。新增金色流动指向线（定向牌落桌后从出牌角色指向目标）、目标红框、当前回合绿框、阵亡灰置印章、手牌整理与弃牌多选/一键选择；弃牌选满数量后才可确认，取消不扣牌。参照原图与摘要见`content/evidence/user-battle-ui-20261117/`，范围和差异见[鼠标界面核对](docs/12-新版PC鼠标交互核对.md)。
键盘可用Tab/Shift+Tab切换控件、Enter或空格激活按钮：选牌后定位合法目标，选牌与目标明确后定位确认，取消返回原手牌；新请求与读档重新定位可用操作。底栏“操作说明”列出完整流程；战斗记录的滚动条支持方向键查看历史，Esc关闭当前弹层。以上为内部开发操作，OL同版本快捷行为仍待核验。

右键手牌可展开完整预览，左键关闭。公开处理区卡面可通过悬停或键盘聚焦展开预览，显示实际花色点数、原牌画面及当前用途；Esc收起预览，不改变选择或放弃响应。顶部“手牌一览”提供当前操作友军的全部手牌，可用键盘选择逐张阅读，包括当前不可用的灰置牌。查看不提交命令；请求切换、读档和新建会刷新可见牌，敌方手牌不展示。此为开发查看流程，同版本OL悬停形态及新增入口的差异仍待核验。

战斗页新增“角色资料”和“界面设置”：角色资料可查看任意座次的公开体力、手牌数、完整技能与未启用原因，查看不切换操作权。技能按钮可筛选当前合法手牌与成本方案；拆顺以牌背槽位选牌，提交前不展示暗牌。在空白处右键取消选择；Esc先收起卡面详情，再取消选择；双击已明确的牌或目标可确认，多个目标或成本仍需手动选择，可在设置中关闭双击。确认、放弃响应、结束出牌继续保留可见按钮。设置提供100%、125%、150%、200%及跟随系统缩放，窗口空间不足时自动适配，减少动态时卡面不再悬停抬起；设置独立保存在`user://battle-interface.cfg`，不进入规则存档。伤害、回复、技能与终局均有文字反馈，不依赖语音。

本轮按用户要求暂缓操作录像采集、录制与回放；不影响其他交互功能开发。正式同版本状态截图、布局比对及Windows系统缩放实测仍需实证完成，不能用本项目截图冒充OL来源或宣称U系列已通过。

首城战役现有独立开发闭环：在战斗页“新局”弹层中点击“首城行程”，选择三种出身之一，经历各自三个事件、可选邀请乡勇并编队，通过故乡撤离、驿路、外城与内城四场真实牌局取得柳平城。支持失败重试、主角不上场、战役与活动牌局一并保存恢复。乡勇启用奋击I阶，学子和农户暂用无技能模板，对手均为通用守军；完整M2内容仍待制作。范围和复现见[首城战役开发闭环](docs/12-首城战役开发闭环.md)。

## 开发入口

工具链候选为.NET SDK 10.0.404、Godot 4.7.2 .NET。脚本优先使用项目内`.tools/`工具，不修改全局shell；新检出需自行安装对应SDK和Godot .NET。当前Windows开发机已在`.tools/`安装同版可移植工具，系统原有SDK不受影响。版本、下载摘要与平台验证见[工具链决策](docs/decisions/0001-toolchain.md)。

```sh
# 规则测试、内容校验、抽牌与基础战斗保存恢复试验
./scripts/check.sh

# 通用角色2对2基础战斗，输出快照、日志及逐决策恢复报告
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-basic 42 build/basic-battle

# 在另一个进程中从最后决策点继续；final.json应与连续版本逐字节一致
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-resume build/basic-battle/checkpoint.json build/basic-battle/resumed

# 六种牌混合对局；另存反无懈链中间和决斗响应快照
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-tricks 42 build/trick-battle
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-tricks-resume build/trick-battle/counter-chain.json build/trick-battle/resumed-counter

# 八种牌混合对局；在暗牌选择点启动另一进程继续
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-hand-tricks 42 build/hand-trick-battle
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-hand-tricks-resume build/hand-trick-battle/hand-choice.json build/hand-trick-battle/resumed-hand

# 武圣、奸雄、奋击I阶及八种牌；从伤后技能询问点跨进程继续
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-skills 42 build/skill-battle
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-skills-resume build/skill-battle/skill-trigger.json build/skill-battle/resumed-trigger

# 基础AI对战；逐决策验证恢复，输出动作评分和原因
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-ai 42 build/ai-battle
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --battle-ai-resume build/ai-battle/ai-decision.json build/ai-battle/resumed-ai

# 三线首城开发闭环，含真实战斗与中途恢复
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --campaign-first-city 42 build/first-city

# 来源冻结严格检查；公开开发资料已采集，正式快照尚未冻结，预期返回1
./scripts/dotnet.sh run --project tools/Sanguo.ContentValidator -- content --require-frozen

# 离线核对OL公开开发素材包（立绘、技能与PC UI图集）
python3 scripts/collect-ol-sources.py content/evidence/ol-public-20261112

# 编译Godot验证场景
./scripts/dotnet.sh restore client/Sanguo.Client.csproj --locked-mode
./scripts/dotnet.sh build client/Sanguo.Client.csproj --no-restore

# 打开战斗开发原型；“新局”弹层可切换至G0抽牌试验
./scripts/godot.sh --path client

# 客户端鼠标拖牌、键盘兼容、完整卡面查看、公开处理牌、缩放、战役与存档恢复回归
./scripts/check-client.sh

# 无头验证Godot调用C#命令与文件保存恢复，同样须在沙箱外启动
./scripts/godot.sh --headless --path client -- --smoke

# 安装同版.NET导出模板后生成Windows验证包；须在沙箱外运行
./scripts/export-windows.sh

# 在独立Windows 11 x64设备解压后，于包目录执行（无需SDK或Python）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify-windows.ps1
```

当前截图版战斗桌面支持悬停抬升放大、拖动整理手牌、拖向合法目标或中央出牌区出牌，以及飞牌、牌背摸牌、伤害/回复/技能与回合反馈。两套`check-client`均包含真实鼠标拖牌回归；动效预览参数和范围见[新版PC鼠标交互核对](docs/12-新版PC鼠标交互核对.md)。

Windows开发机可在仓库根目录使用原生入口（要求锁定的SDK、Python 3；导出还要求Godot 4.7.2 .NET及匹配的导出模板）：

```powershell
pwsh -NoProfile -File .\scripts\check.ps1
pwsh -NoProfile -File .\scripts\check-client.ps1
pwsh -NoProfile -File .\scripts\export-windows.ps1
```

`export-windows.ps1`优先读取`SANGUO_GODOT`，也可从`.tools/`或`PATH`查找编辑器。开发机有SDK时，随包验收可提供探针运行日志，但不能满足“无开发SDK目标机”验收条件。

Git默认使用原生`.git`。部分受限会话会重新施加拒绝写入规则，表现为无法创建`index.lock`；本批会话因此使用从当前`.git`新复制的`.tools/git-milestone-20261116`元数据提交，不修改权限。历史`git-writable.ps1`使用另一份独立元数据镜像，不会自动跟随普通Git更新；使用任何镜像前须核对基线或新建副本。镜像提交不会更新原生本地引用，退出受限会话后须核对远程与本地状态再同步，避免把已提交改动重复提交或覆盖工作区。

`Sanguo.slnx`包含不依赖Godot的库、命令行工具及测试；客户端单独构建。`content/cards/g0-probe.json`的八张牌只是技术试验数据，所有效果均标记`declared-only`。`Sanguo.Simulator`原入口仍验证抽样；`--battle-basic`、`--battle-tricks`和`--battle-hand-tricks`分别使用三牌、六牌、八牌合成场景，`--battle-skills`加入技能开发配置，均使用`rules.basic-development.v4`，不加载正式OL武将内容包或G0声明牌。拆顺与武圣当前只支持手牌成本，尚无装备区和判定区。基础战斗开发快照已升至格式4，旧格式1至3明确拒绝为不兼容；G0存档不变。Godot默认进入独立合成战斗场景，不与模拟器场景混读；战斗档位于`user://battle-development/session.json`，保存保留上一份有效`.bak`。客户端烟测参数为`--battle-smoke write|resume <专用目录绝对路径>`，只供回归使用；默认对局由玩家操作两名友军，敌方AI每0.45秒推进一个普通决策，无懈窗口自动略过空询问并处理AI响应，玩家响应不限时。OL规则、武将和界面来源清单仍待实证冻结，内容校验通过不代表来源或M1验收通过。规则边界、快照和复现步骤见[基础战斗开发规则](docs/10-基础战斗开发规则.md)及[技能开发规则](docs/11-技能开发规则.md)。

OL公开开发资料已保存到[`content/evidence/ol-public-20261112/catalog.json`](content/evidence/ol-public-20261112/catalog.json)：六名标准武将的原画与完整技能、八组PC界面图集及坐标、官方历史战斗截图，共33份原始文件。可据此推进开发；同一客户端版本和逐步交互证据在对应还原验收前补齐，不阻塞通用战斗核心、内容工具和剧情配置。采集与校验方法见[来源登记与校验](docs/07-来源登记与校验.md)。

Windows自动验收会检查文件摘要、固定状态哈希、跨进程保存恢复、命令去重和损坏档备份回退，并将报告与日志写入独立临时目录。当前Windows开发机已生成自包含验证包并验证文件清单及跨进程写档恢复；本沙箱的系统根证书库错误写入包清单警告，自动验收未通过。仍需无SDK独立设备的离线及窗口验收，不能因此关闭G0。详细步骤见[Windows验收流程](docs/08-Windows验收流程.md)。

- 2D节点地图、人物立绘、剧情事件与卡牌桌面，核心完全离线。P0/M1战斗原型即还原三国杀OL的对局UI与交互，按同一OL PC界面快照验收。
- 主角形象与技能原创。出场武将的立绘和完整技能使用《三国杀Online》已存在且登记版本的内容；乡勇、杂兵等通用角色可使用本项目的基础模板。
- 招募条件满足即可永久加入，名册无人数上限。人物信息和条件供玩家查询，招募顺序与搭配由玩家自行选择，三条故事共用武将池，交集、出场情境和招募路径可随主角剧情变化；人物列表保持中立排序，不预选搭档。
- 三种出身各有独立的完整主角故事，并固定对应伤害输出、过牌控场、坦克卖血技能路线，主角沿所属路线I至III阶进阶；成长以永久招募、卡牌攻城和主角技能为主。
- 每方场上1至4个单位、双方最多8个，支持多打少；主角可不上场。主线约1/2处完成双将协同剧情后开放双将，主副共用一个位置。
- 主线约3/4处完成车轮接战剧情后开放车轮战，每方含首发最多三批。当前批全灭后，观察对面公开存活阵容再部署未登场人物；存活状态与牌堆延续。
- 战斗只由卡牌歼灭及合法替补耗尽决定最终胜负，攻城与守城均通过武将牌局结算；领地承载归属、道路与内容解锁。
