# 三国行纪 项目规划

以《三国杀Online》武将与卡牌规则为基础的三国背景策略单机游戏。玩家从平民出发，自由招募武将，通过武将卡牌战斗攻城略地，选择三种背景之一，经历各自从无名小辈到统一天下的完整故事。《三国行纪》为暂定工作名。

当前阶段：M0/G0开发已启动，已建立C#工程、内容校验、固定随机流、可保存恢复的抽牌试验与Godot验证场景。尚未实现P0战斗，也未通过G0全部验收。实际进度见[开发进度](docs/06-开发进度.md)。

## 开发入口

工具链候选为.NET SDK 10.0.404、Godot 4.7.2 .NET。脚本优先使用项目内`.tools/`工具，不修改全局shell；新检出需自行安装对应SDK和Godot .NET。版本、下载摘要与平台验证见[工具链决策](docs/decisions/0001-toolchain.md)。

```sh
# 规则测试、内容校验与保存恢复试验
./scripts/check.sh

# 来源冻结严格检查；当前清单仍待采集，预期返回1并列出待完成项
./scripts/dotnet.sh run --project tools/Sanguo.ContentValidator -- content --require-frozen

# 编译Godot验证场景
./scripts/dotnet.sh restore client/Sanguo.Client.csproj --locked-mode
./scripts/dotnet.sh build client/Sanguo.Client.csproj --no-restore

# 打开验证场景；macOS上的Codex必须经权限流程在沙箱外启动
./scripts/godot.sh --path client

# 无头验证Godot调用C#命令与文件保存恢复，同样须在沙箱外启动
./scripts/godot.sh --headless --path client -- --smoke

# 安装同版.NET导出模板后生成Windows验证包；须在沙箱外运行
./scripts/export-windows.sh

# 在独立Windows 11 x64设备解压后，于包目录执行（无需SDK或Python）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify-windows.ps1
```

`Sanguo.slnx`包含不依赖Godot的库、命令行工具及测试；客户端单独构建。`content/cards/g0-probe.json`的八张牌只是技术试验数据，所有效果均标记`declared-only`。`Sanguo.Simulator`目前仅验证抽样与恢复，不是战斗模拟器。OL规则、武将和界面来源清单仍待实证冻结，内容校验通过不代表来源或M1验收通过。

Windows自动验收会检查文件摘要、固定状态哈希、跨进程保存恢复、命令去重和损坏档备份回退，并将报告与日志写入独立临时目录。人工窗口及离线验证仍需记录；当前尚无Windows运行证据，不能因此关闭G0。详细步骤见[Windows验收流程](docs/08-Windows验收流程.md)。

## 产品标准

- 2D节点地图、人物立绘、剧情事件与卡牌桌面，核心完全离线。P0/M1战斗原型即还原三国杀OL的对局UI与交互，按同一OL PC界面快照验收。
- 主角形象与技能原创。出场武将的立绘和完整技能使用《三国杀Online》已存在且登记版本的内容；乡勇、杂兵等通用角色可使用本项目的基础模板。
- 招募条件满足即可永久加入，名册无人数上限。人物信息和条件供玩家查询，招募顺序与搭配由玩家自行选择，三条故事共用武将池，交集、出场情境和招募路径可随主角剧情变化；人物列表保持中立排序，不预选搭档。
- 三种出身各有独立的完整主角故事，并固定对应伤害输出、过牌控场、坦克卖血技能路线，主角沿所属路线I至III阶进阶；成长以永久招募、卡牌攻城和主角技能为主。
- 每方场上1至4个单位、双方最多8个，支持多打少；主角可不上场。主线约1/2处完成双将协同剧情后开放双将，主副共用一个位置。
- 主线约3/4处完成车轮接战剧情后开放车轮战，每方含首发最多三批。当前批全灭后，观察对面公开存活阵容再部署未登场人物；存活状态与牌堆延续。
- 战斗只由卡牌歼灭及合法替补耗尽决定最终胜负，攻城与守城均通过武将牌局结算；领地承载归属、道路与内容解锁。

## 交付规模与技术

| 项目 | 当前目标 |
| --- | --- |
| 技术路线 | Godot .NET与纯C#规则核心；候选Godot 4.7.2、.NET 10 LTS，G0验证后锁版 |
| 战斗原型 | P0八种牌效果、2名OL武将及奋击I阶；OL式桌面、武将框、手牌与技能操作、响应及结算反馈；支持1至4对1至4，UI与规则分别验收 |
| MVP | 三种背景各自45至90分钟至首城切片及对应I阶；6名OL武将、每线3名可招募；每线3主线单元加5个共享支线，共14逻辑单元；6基础遭遇、1座可占城 |
| 1.0完整版本 | 每条背景故事及适量支线20至30小时；至少100名不同OL武将，原则上全部可永久招募；三套完整主角故事，武将按剧情交集参与；6区域、24城、每线15主线单元加25个共享支线，共70逻辑单元；30基础遭遇、3类结局取向及各线独立尾声 |
| 开发资源 | 单人全职主导，主角、通用角色、场景与音频按阶段采购或外包，OL武将资源按目录核验集成 |
| 工期基线 | MVP原20周为待重估目标；旧3300小时、144周估算不覆盖三套故事与原型UI还原；M0登记界面快照并拆分工作量，M1及三线样板实测后重排 |

1.0的100名按不同人物计数，同人异版、皮肤、主角、杂兵及图鉴占位不充数。轻量化仅减少出场和招募剧情制作量，每名OL武将仍需完整技能、对应立绘及规则验证；主线通关不要求全收集。招募范围暂按百人均可永久招募规划，具体首发名单与OL版本在接入清单中逐人冻结。台词文字、字幕及必要提示先完成；技能、阵亡短语音按接入难度分阶段加入，长剧情配音后置。缺语音不阻断战斗。

M0登记OL规则快照、具体武将版本、完整技能、立绘与皮肤来源；主角、通用角色及战役模式分别定义。公开包使用范围按素材台账确认，正式武将展示采用登记的OL资源。
