# 首城战役开发闭环

日期：2026-11-16。范围：`campaign.first-city-development.v1`，可操作的战役工程切片。不是M2首城MVP验收；正式OL人物、五个共享支线、六基础遭遇、三种完整I阶及45至90分钟体验仍待制作。

## 实际玩法

打开客户端，在自由战斗顶部点击“新局”，再点击弹层中的“首城行程”，选择乡勇、寒门学子或山野农户，再点击“新行程”。每种出身有三个独立事件、各两个选项；选择和首城后果随档保留，序章选择在各线结语中回响。选择目前影响叙事记录，不修改卡牌胜负或额外发资源。

行程依次通过故乡撤离、驿路通行、柳平外城、柳平内城四场牌局。前三个事件分别对应制作大纲前三单元，攻城单元包含外城和内城两阶段。外城获胜只开放内城编队，最终内城获胜才取得`city.liuping`。每场独立发牌并恢复体力，两阶段不是车轮战，不延续上一场的牌堆和伤势。失败保留已通过阶段、剧情选择和永久名册，点击“重新编队挑战”以新尝试编号和确定的新牌序再战。

驿路阶段可邀请一名原创通用乡勇永久加入；直接选择剧情或出战可跳过招募。编队从永久名册中选择至少一人，主角可不上场，已加入者不因失败或剧情选择离队。当前名册实际只有主角与可选乡勇；这是切片内容数量，不能作为正式名册容量或招募系统上限。三种出身的剧情各自独立；乡勇主角启用奋击I阶，学子、农户和可选乡勇使用无技能通用模板，界面首页明确提示。没有把未实现的筹策、坚忍或吕布技能包装为已支持。

四场敌方均为单名通用守军，体力依次3、4、4、5。该开发难度让没有同伴和技能的路线也能通关；不对应冻结OL守将配置或最终难度。战斗沿用八牌开发核心、基础评分AI、完整卡面预览、键盘流程和公开记录。只有敌方自动行动，玩家操作自己选择出战的所有人物。战斗中“返回行程”可暂停；结束后点击该按钮提交战果，继续下一事件或重试。

## 状态与事务

- `CampaignCore/FirstCity`定义独立开发进度和九个事件，不改变G0的`CampaignState`。
- `FirstCitySession`是单线程应用入口；Godot主线程顺序提交剧情、招募、编队、开战、结算和重试。战斗使用它持有的`BasicBattleSession`，`BattleInteraction`管理同一会话的预览和实际提交，不复制另一场战斗回来结算。
- 剧情命令携带唯一ID及预期战役版本。相同命令重提返回原回执，同ID不同输入、过期版本和越阶段操作拒绝。战斗仍单独检查控制者、实体、请求及牌局版本。
- `resolve`不接收胜方或奖励参数，只读取当前战役持有且已经结束的牌局；一次更新战果历史、挑战阶段、最终领地状态并清除活动牌局。旧命令重提不会重复结算。没有独立“占城”或“宣告胜利”入口。
- 战果历史保留每场完整终态、合法命令和出战配置。恢复先检查阶段、尝试号、名册、牌组和版本，再从种子重放所有剧情命令与各场战斗命令，最后比较整个快照。仅修改体力、牌面、种子、选择记录或归属并重算摘要，仍会被拒绝。这是确定性一致性检查，不是对持有本机文件的用户实施防作弊认证。

2026-11-17起，九个事件、十八个选项与六段结语由`content/campaigns/first-city.json`提供，严格校验后作为嵌入资源读取；格式、编辑及大纲引用见[首城事件数据契约](14-首城事件数据契约.md)。两名候选、一个可占城和四场遭遇仍是编译期开发配置。任务条件、地点地图、五共享支线、OL人物招募替代路径、外交、奖励和技能成长未实现；不以本切片代替完整战役架构。

## 存档

`FirstCitySnapshotCodec`使用格式`sanguo.first-city`版本1，引擎`0.1.0-first-city-development`。内容摘要覆盖事件文字、选项后果、结语、牌组、单位配置与启用技能。G0和基础战斗格式、历史摘要保持不变。

每种出身单独使用`user://campaign-development/{damage|control|tank}/session.json`，保存战役、当前牌局和命令记录。战斗中的保存和恢复均走战役槽，不会只恢复牌局而留下另一份战役进度。恢复后回到行程页，再点击“继续牌局”；未确认的选牌或方案不入档。

临时文件刷新并解码校验后替换主档，保留上一有效`.bak`；主档缺失或损坏时回退，不兼容档拒绝读取及覆盖，损坏主档不会覆盖有效备份。新建行程或切换到自由战斗须确认离开当前进度，已有文件直到主动保存时才替换。当前每线一个手动槽，没有自动保存、正式存档迁移及多槽管理。

## 界面约束

战役页以行程先后、当前事件、永久名册与具体决定组织内容，沿用战斗页墨绿和金色；不将其作为OL对局界面还原。色板为底色`#182D29`、次表面`#29433B`、动作金色`#DEC68D`、正文`#F3EDDF`。系统中文字体承担正文与标题，通过18/22/28/32/36字号建立层级。顶部保留出身、存取和自由战斗入口，事件区域独立纵向滚动，底部显示结果及错误。原生按钮、选择控件和勾选项支持Tab及Enter/空格；主动作有明确聚焦描边，焦点跟随滚动。没有新增自动动画或外部字体依赖。

设计使用`ui-ux-pro-max`与`frontend-design`核对，通用营销页配色建议不适用于现有游戏，因此遵循已建立的墨绿桌面风格，采用技能中的焦点、阅读层级、可见操作及滚动可达性原则。960与1280窗口回归不替代系统缩放或辅助技术验收。

## 开发复现

```sh
./scripts/check.sh
./scripts/check-client.sh  # macOS须在沙箱外启动Godot

# 三线自动真实牌局、恢复与命令去重验证
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --campaign-first-city 42 build/first-city

# 从外城牌局第12条命令后的决策点在另一进程继续
./scripts/dotnet.sh run --project tools/Sanguo.Simulator -- --campaign-resume build/first-city/damage/checkpoint.json build/first-city/damage/resumed
cmp build/first-city/damage/final.json build/first-city/damage/resumed/final.json

# 专用测试目录内验证真实客户端按钮、键盘选项和中途恢复
./scripts/godot.sh --headless --path client -- --campaign-smoke "$PWD/build/campaign-client"

# 真实渲染截图；可附加战役快照路径查看当前事件或首城结语
./scripts/godot.sh --path client -- --campaign-preview "$PWD/build/campaign-story-960.png"
```

CLI每条路线输出`checkpoint.json`、`final.json`、`report.json`，恢复过程的主档与备份存入输出目录的独立`runs`子目录，以免旧开发内容阻止重复回归。客户端烟测同样在给定目录内创建独立子目录，不触及正常玩家槽位。步数或重试保护只返回失败，不生成胜利。

新增23项xUnit覆盖三种出身、两组选择、可选招募和独行通关，失败重试、主角不上场、占城阶段、非法编队、命令幂等和过期输入、嵌套战斗预览、带有效摘要的语义篡改拒绝、未知和重复JSON字段，以及文件备份和不兼容保护。客户端烟测覆盖两种窗口下三条路线共六次完整行程、真实玩家按钮、Tab/Enter入口和剧情选项、离开确认的Esc取消、活动牌局的保存恢复、纯同伴编队及最终归属恢复；包含主动放弃玩家响应的失利路径。
