# 三国行纪 战斗规则与验收附录

日期：2026-11-12　状态：工程规格与验收合同，完整参照规则清单在M0冻结

本附录定义《三国杀Online》规则与武将接入契约，以及主角、单双将、车轮和领地的验收场景。出场武将的立绘、基础属性和完整技能以登记的OL具体版本为准；主角技能为原创，乡勇杂兵等通用单位使用基础卡牌模板。项目战役模式规则与OL武将定义分别存储和校验。

## 1 OL规则与人物来源

### 1.1 范围

| 项目 | 当前基线 |
| --- | --- |

| 武将来源 | OL已有武将，每人选择一个明确版本，立绘使用该版本在OL实际可用的原画或皮肤 |

MVP的武将内容为关羽、赵云、张辽、华佗、曹操、吕布，逐人登记OL版本、完整技能与立绘。1.0完整版至少交付100名不同人物的OL武将，暂按至少100名均可永久招募规划；同人异版、皮肤、主角、杂兵与图鉴占位不计入人数。三种背景各自交付完整主角故事，武将依本线事件交集安排剧情，没有深交者轻量出场和招募；不设固定重点武将人数。轻量化不改变武将完整技能与验证要求；依赖的规则或牌机制随接入清单一并实现，只有完整案例通过后才进入可战斗内容包。人物数量与名册容量分别定义。

P0/M1除本附录的规则案例外，必须通过[战斗界面与交互还原规范](05-战斗界面与交互还原规范.md)的U系列原型必验项；还原OL PC桌面与操作流程是独立门槛。台词字幕与文字提示必需，角色短语音按难度分阶段实现，缺音频不得影响规则。

### 1.3 技能完整性与模式条件

武将技能的原文本、条件、次数和数值保存在来源定义中，实现按其完整语义处理。公开队伍、自由双将和车轮接替属于模式层，不修改武将原技能。原技能要求主公身份而当前模式没有该身份时，条件自然不成立；成为双将主将不等于获得主公身份。

技能使用的性别、势力等角色属性从OL来源取得。战役敌我队伍不直接等同于原技能势力；双将单值属性与跨势力组合按照本项目明示的模式裁定派生，原技能定义仍保持一致。任何需要额外机制的武将先完成依赖与案例，关卡难度通过阵容、人数、座次和模式调整。

每张实体牌登记唯一实例ID、花色、点数和牌定义，牌组数量按OL来源清单校验。原型测试牌组与完整OL内容包分别标识；公开包资源以素材台账中适用范围确认的条目为准。

## 2 回合与基础处理

回合阶段采用准备、判定、摸牌、出牌、弃牌、结束六个明确阶段；参照版若用不同术语，建立名称映射。阶段跳过与“进入但没有执行动作”分开表示，避免阶段触发技能错误。

默认摸牌、主动使用杀次数、弃牌手牌上限和起始手牌按参照版配置。通常情况下的默认值可用于实现初稿，但冻结前不得把项目习惯替代规则源。临时加成和技能替代均通过规则上下文显式记录。

开局的先手与座次由遭遇配置决定并展示；牌堆随机洗牌。主角不自动先手，也不额外发好牌。独立牌局重置体力、手牌、装备、次数和牌堆，车轮批次不属于独立牌局；战役叙事伤势不影响下场出战资格，战斗死亡不清除永久招募状态。

### 2.1 使用牌流水线

```text
请求使用
→ 验证时机、来源和支付
→ 确认目标与距离
→ 实体牌移入处理区，记录虚拟牌转换来源
→ 按参照时机处理使用与目标相关技能
→ 为目标建立效果与响应窗口
→ 完成各目标结算及嵌套效果
→ 按规则处理实体牌去向
→ 完成当前使用，检查后续触发与关卡目标
```

这是一条工程框架；个别牌、技能的取消、额外目标和替代效果由具体裁定覆盖。每个效果帧都保留来源、支付卡、目标、当前游标与取消原因。

响应牌和主动使用牌分开建模。无中生有、桃等牌不应被错误套用杀的距离与次数；决斗要求的出杀不能被算成一次普通出牌阶段的主动杀。

### 2.2 距离与座次

活角色构成环形有效座次；阵亡位置是否跳过以及武器、坐骑、技能的修正顺序按参照版裁定。UI应能解释“座次距离—坐骑修正—技能修正—攻击范围”的来源。

本项目战役在开战前固定座次，常用双方交错布局，具体写入遭遇数据。拖动头像仅为显示操作，不能改变距离。有效目标检查和最终提交时都重新验证，防止响应后状态变化仍使用过期目标。

### 2.3 濒死与死亡

伤害和失去体力是不同路径，不能触发完全相同的一组技能。体力不足时进入独立濒死流程，按参照顺序收集救援；救援完整结算后，体力仍不足才进入死亡。

死亡清理需要处理手牌、装备、判定区、当前响应权、后续座次、来源技能和待结算目标。公开队伍模式不执行身份奖惩。死亡引发的触发、同批次死亡和双方同归于尽处理完毕后，先检查车轮替补，再判整场终局。

本场死亡照常清理，全灭后只有无合法替补才判负；整场终局后保留永久名册和主角技能阶位，可自由参与下一场；同场车轮战已登场人物不能再派入下一批。不引入俘虏扣留、永久死亡或伤势禁用。

## 4 武将与原创技能

### 4.1 MVP六名人物的规则覆盖

| 人物 | 重点工程问题 |
| --- | --- |
| 关羽 | 按参照技能转换牌；原实体牌花色点数、使用与响应资格 |
| 赵云 | 杀与闪的转换上下文，不能把不合法时机变成合法 |
| 张辽 | 摸牌阶段替代、选择人数、目标是否有手牌、暗牌获得 |
| 华佗 | 弃牌成本、回复、回合外救援与技能使用时机 |
| 曹操 | 伤害后获取牌、造成伤害的实体牌是否仍可获得、多目标去向 |

此表不代替完整技能文字。只有参照登记中确认的版本才形成实现合同。每名武将至少覆盖正常触发、条件不满足、放弃、次数或阶段限制、与另一技能交互五类案例。

### 4.2 三种主角I阶的确定语义

三种出身均为4体力上限，开局绑定一种核心技能；技能升级只能在该路线内进行。具体I至III阶候选以制作总纲第6.2节为准，以下规则必须转为明确效果帧和案例。

- **奋击：** 在主角出牌阶段使用杀、最终目标已确认且只有一人后选择发动，每出牌阶段限一次。额外支付牌必须是另一张手牌，不能复用杀的实体牌或随意拿装备区支付。接受并支付后计次；该useId对该目标首次伤害加1。被闪、无效或最终没有伤害不退成本，不增加使用杀次数。II阶按支付时体力决定是否免额外弃牌；III阶的伤后摸牌每主角回合限一次且主角仍存活。
- **筹策：** 自己出牌阶段主动发动，阶段限一次；弃1手牌为成本。I、II阶目标是有手牌的敌方，目标自行弃1手牌，主角分别摸1或2。III阶允许目标从手牌或装备区自行弃1，不能弃判定区牌。没有“观看敌方暗牌”步骤。支付后目标因合法触发失去可弃牌时跳过该弃牌步骤，不重收费用；主角仍存活时继续后续摸牌。重复命令不能再次支付、弃牌或摸牌。
- **坚忍：** 每角色回合限一次，受到伤害及其濒死救援全部处理完成、仍存活后可摸1，II阶起摸2；失去体力、伤害被完全防止、未救回的死亡均不触发。选择放弃不消耗次数，成功发动后计次。III阶增加自己结束阶段的可选自疗：已受伤且有2手牌时弃2回复1，阶段限一次；不能在满体力或其他角色结束阶段发动。

“每角色回合”“每出牌阶段”“每完整牌局”与“车轮批次”不同。存活武将的次数不因对面换批而刷新。出身、技能阶位在整场开战锁定，换批不能换路线或临时升级。主角作为双将主将或副将时，技能属于共享战斗单位，不能按两个人重复触发。

## 13 支持范围与发布标记

规则能力矩阵每项使用“未开始、实现中、案例通过、集成通过”四种状态。已实现但未核对规则源的功能不能写为“OL规则支持完成”。开发包明确标记P0子集或MVP规则包版本。P0规则范围与UI还原范围分别标记；通过纯规则案例不代表OL界面还原通过，界面相似也不代表未实现牌与技能已受支持。

MVP只有在完整冻结牌包、6名武将及奋击、筹策、坚忍I阶的在用交互通过案例与集成后，才可标为本项目MVP规则支持完成；它不等于所有三国杀模式、全部武将和扩展均被支持。

后续每新增一个人物或扩展包，先做能力与冲突清单，再补裁定和回放样本，最后开放给内容配置。战斗规则包升级必须同时评估活动战斗存档的兼容策略。

1.0发布须逐人通过至少100名不同OL武将的接入验证及S-009至S-013，三套完整主角故事通过O-007至O-011，交集事件及轻量入口在各线可达；暂按百人均可永久招募的制作范围验收招募路径。MVP的6人子集、仅来源登记完成的百人目录或后续补人计划均不能替代1.0交付。
