# 三国行纪 战斗界面与交互还原规范

日期：2026-11-12　状态：原型验收规格，具体OL界面快照待M0采集冻结

本规范将**还原《三国杀Online》的战斗UI与交互**列为P0/M1战斗原型的必要交付。原型须能以OL式桌面完成完整牌局，规则模拟、调试面板或只有相似配色的静态桌面不能代替该验收。规则范围仍为P0八种牌效果、2名OL测试武将与奋击I阶，不因此扩大为全部OL玩法。

## 1 参照版本与还原证据

默认以《三国杀Online》PC端八人牌局的同一套界面为参照，M0记录实际客户端或网页端版本、界面皮肤、分辨率、缩放与采集日期。本文定义还原要求，不声称已取得完整截图或已核验具体快捷键。

参照包`content/manifests/sgsol-battle-ui-reference.json`至少登记：`referenceId`、`sourceGame=sgs_online`、端与版本、界面主题、分辨率、截图及录像索引、各交互步骤、资源来源、文件摘要、已核对状态和项目适配差异。只使用同一快照，不混入十周年、移动端或其他同名产品的界面与操作。

M0至少采集以下状态：空闲桌面、自己的出牌阶段、选牌与选目标、杀闪响应、决斗交替响应、连续无懈、技能发动与取消、目标区域选牌、弃牌和濒死救援。P0不支持的装备、判定等界面可先采集，具体可操作流程留到MVP，不用伪造规则支持来填界面。

还原比对以截图与逐步操作录像为准。网页文字资料、其他产品视频或凭记忆描述不能独立作为按钮位置、双击、右键和快捷键行为的验收依据；相关未决项须在M1通过前核验收口。

## 2 UI还原范围

| 区域 | P0/M1必要交付 | 比对重点 |
| --- | --- | --- |
| 战斗桌面 | 按OL快照还原桌面构图、边框、纹理、主要色彩、信息层级与空间比例 | 与同分辨率参照截图并排及叠图检查，不能只保留配色 |
| 武将与座次 | 对应OL立绘、武将框、姓名、体力、手牌数、技能区、当前回合及响应者标记 | 可见信息与状态位置稳定；1至4对1至4时正确映射有效座次 |
| 手牌与操作区 | OL式手牌排列、悬停展开、选中抬起或描边、不可用灰置、技能按钮与确认区 | 花色点数、牌名与被覆盖牌可辨认；当前手牌归属明确 |
| 中央处理区 | 出牌展示、来源与目标指向、响应牌、伤害回复及技能文字反馈 | 可追溯正在结算的来源和目标，动画不挡必要输入 |
| 装备与判定区 | M1保留参照布局和空态；MVP接入实际装备、判定与状态图标 | 不把未实现规则显示为可用；详情不泄漏暗牌 |
| 提示、日志与弹层 | 当前阶段、操作提示、技能或选牌弹层、可展开日志、卡牌与技能说明 | 布局和交互按快照；单机新增的因果详情置于扩展层 |

按OL八人桌面的主操作区与周边座次组织，不继续使用原规划的“固定上排四敌、下排四友”独立布局。当前操作友军映射到底部手牌与主操作区，其余有效单位沿参照的周边位置展示；具体锚点与视角切换方式在M0截图映射表冻结。视角映射不改变规则座次、先后手或距离，不创建额外单位。

地图、人物名册和剧情页继续使用本项目设计；战斗页的布局、部件视觉及操作状态以OL还原为优先约束。无账号大厅、商城或匹配流程的制作要求。基准1920×1080，最低验证1280×720及125%、150%、200%系统缩放；适配时保留结构与操作关系，记录与参照的必要差异。

## 3 交互流程合同

| 场景 | 必须还原及验证的行为 |
| --- | --- |
| 使用牌 | 选中合法手牌，显示可选目标，满足数量与条件后允许确认；重选和提交前取消不消费牌、次数或随机流 |
| 使用无目标牌 | 以冻结快照的操作完成确认，不能强迫点选虚构目标；所选牌和即将发生的动作可见 |
| 杀闪与决斗 | 明示当前需要的响应、来源、操作者与可用牌；支持合法响应或放弃，响应完成后回到正确的结算上下文 |
| 无懈链 | 展示当前待抵消对象与链层级；逐请求响应或放弃，结束后恢复原效果，不用重叠弹窗掩盖前后关系 |
| 主动与触发技能 | 主动技能按时机启用；触发技能按请求询问发动或放弃，转换牌显示虚拟牌与实体成本；确认前可回退 |
| 拆顺选牌 | 按目标允许的区域展示牌或牌背，暗牌不可透视；选择、取消与提交遵守当前请求 |
| 弃牌 | 显示应弃数量、可选区域和已选数量，满足规则后才能提交；不把取消误作结束回合 |
| 濒死救援 | 显示被救者、当前体力、所需回复和当前响应角色，只允许当前时机合法的牌或技能 |
| 确认、取消与结束 | 位置、标签、启用状态和行为按快照核验；取消本次选择、放弃响应、结束出牌阶段分别处理，不能共用错误命令 |
| 悬停、右键、双击与键盘 | 悬停说明、取消操作、快捷提交等逐项依据参照录像登记；未核验不默认绑定。确认与取消保留可见按钮及键盘路径，不强制拖拽 |

选择只改变客户端预览，合法性以规则核心的动作描述与提交校验为准。服务端或联机倒计时不直接移植：本项目为离线单机，默认响应不限时，不因超时自动出牌、放弃或结束回合；这是明示的项目差异。

用户操作后100毫秒内给出可见反馈；选中、悬停、禁用、待响应和已提交状态可区分。无效动作在原位置说明原因，未确认不得误扣成本；确认后禁止重复提交。关闭说明面板不等于放弃响应。所有重要提示都有文字或图标，语音和颜色不单独承载必要信息。

## 4 单机队伍适配与实现边界

玩家控制最多四名友军，界面始终标明“正在操作谁、因何获得操作权”。实际需要操作的友军由当前决策请求指定，自动展示其手牌和技能；查看其他友军资料不会把操作权转给该单位。切换后清理旧选择，不把上一个单位的已选牌或目标带入新请求。

OL式手牌操作与角色框用于单将原型；双将主副共框、车轮部署和对手存活状态展示在M3后沿此规范扩展，不作为M1前置。敌方暗牌、未来牌序和未公开后备始终按规则隐藏。

界面流程采用“空闲—选择牌或技能—选择成本或目标—待确认—已提交等待结算—下一请求”。`PendingDecision`和`BattleView`提供操作角色、合法动作、选择数量、可见区域和当前提示。Godot客户端只生成命令、显示观察和播放已提交事件，不因动画完成、按钮灰置或音频结束决定结算结果。

## 5 台词与配音的难度取舍

本轮选择：**文字提示与字幕为必需；角色短语音分阶段接入；长剧情配音后置。** 不要求原型全角色、全皮肤或全剧情配音，也不以缺配音推迟核心UI与交互还原。

| 层级 | 实施决定 | 验收 |
| --- | --- | --- |
| A0 文字与字幕 | M1实现完整规则提示；已配置角色台词随技能或阵亡事件显示字幕，暂无台词时用明确事件说明 | 关闭声音仍可完整操作和理解结算；原型角色无空白必要提示 |
| A1 武将短语音 | MVP优先为已登记且易取得适用音频的角色接入技能、阵亡短语音；M1可用1名测试武将验证播放，音频缺失不阻断M1 | 台词、人物版本或皮肤与触发事件匹配；字幕可见、可静音，重复事件不重播 |
| A2 扩充与剧情语音 | 依据实测接入量扩充短语音；主角关键片段可选，三套长剧情不承诺全配音 | 逐项计入工作量和资源表，不挤占三套故事及百人武将交付 |

优先验证短语音的资源映射、解码与播放成本，不先做重新录制、音色复刻或整篇合成配音。每条配置登记`cueId`、人物及版本或皮肤、触发事件、台词文本、音频可空引用、来源与适用范围；缺音频走字幕回退。BGM、效果音和角色语音分组调节，连续技能限并发或排短队列，避免多句叠播；不阻塞牌局等播完。

字幕与语音由已提交的规则事件驱动；音频随机变体只使用表现随机流。事件ID去重，读档默认不重播已提交旧语音，主动观看录像可按播放游标重播。1倍、4倍、跳过动画、关闭语音及缺失音频均应得到同一规则结果与下一决策。

## 6 还原验收与交付包

M1交付可运行Godot战斗客户端、冻结OL界面参照包、逐场景对照截图、配对操作录像、必要项目差异表及未完成项。P0使用已支持的牌与技能完成UI验证，不把其他牌面测试夹具计入规则支持。

| ID | 验收场景 | 通过条件 |
| --- | --- | --- |
| U-001 | 同分辨率桌面与操作状态对照 | 布局、武将框、手牌区、提示和按钮状态按参照逐项通过；差异有原因与记录，不能仅用“风格接近”验收 |
| U-002 | 出牌、目标选择、重选与取消 | 逐步对应参照操作；可用与不可用状态准确，取消无费用，确认后只提交一次 |
| U-003 | 杀闪、决斗、无懈与濒死响应 | 来源、操作者、合法响应、放弃和返回流程正确，复杂链无面板遮挡 |
| U-004 | 关羽转换与奋击成本；曹操伤后获牌 | 技能启用、询问、成本选择、取消及结算反馈与冻结技能及UI合同一致 |
| U-005 | 四友军控制与全部16种人数配置 | 当前操作对象明确，切换不串牌或目标，不改变座次，不展示敌方暗牌 |
| U-006 | 缩放、键盘和减少动态 | 720p及系统缩放下卡牌信息、响应和按钮可用，焦点可见，不依赖拖拽、颜色或声音 |
| U-007 | 等待输入时存档恢复及重复确认 | 恢复正确操作角色、合法动作与响应上下文；过期请求被拒绝，无重复支付 |
| U-008 | 无语音、缺音频与短语音播放 | 字幕或文字提示完整；播放、静音与缺文件不影响结算和存档，读档不重复旧语音 |

U-001至U-007及U-008的无语音回退是M1必要验收。U-008的实际短语音播放在启用A1时补验；MVP补充装备、判定、多成本和多目标技能的对应UI流程。纯规则自动化与UI还原分别通过，不能互相替代。
