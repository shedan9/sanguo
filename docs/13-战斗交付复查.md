# 战斗交付复查

日期：2026-11-17。结论：上一轮补齐动效不能证明完整成品已经完成。本轮以实际输入、弹层可读性、滚动与缩放、终局和存档闭环重新检查；最终改动统一在main提交推送，不另开分支，不强推覆盖已有历史。

## 发现与修复

| 问题 | 处理 |
| --- | --- |
| 截图版拖牌与远程战役、卡面详情及设置分处不同历史 | 保留双方提交历史；同一牌桌接通三线首城、活动战斗保存恢复、完整卡牌说明、只读手牌一览、公开处理牌转换用途与反制对象、已有键盘通路及设置 |
| 悬停放大后仍不清楚卡牌用途 | 手牌和处理牌悬停/聚焦展开完整说明，底部保留单行提示；牌背选择弹层优先显示，不被卡面预览遮挡 |
| 部分分辨率与缩放下滚动条将手牌区撑出窗口 | 牌高预留滚动条空间，手牌宽度按实际牌数计算；缩放修改期间避免中间尺寸重入，离场停止重建界面 |
| 拖动长手牌无法到达隐藏位置，切换友军丢失整理结果 | 拖牌到手牌区域两侧自动滚动；按友军分别保存显示排序，不改规则牌序和存档 |
| 右键/Esc取消拖动不完整，切场景残留窗口事件 | 取消或失焦清除浮牌并保留战斗状态；离开战斗解除窗口事件订阅，避免旧页面继续响应 |
| 减少动态设置未作用于新动效 | 停用悬停抬升、飞牌与命中粒子，停止指向光点运动；保留静态公开牌和文字结算，不改变规则 |
| 终局只有短暂飘字，新增结算弹层在真实渲染中被最小内容尺寸撑出屏幕 | 结算内容改为受窗口约束的明确布局，禁用弹窗自动随内容扩张；真实渲染核对弹窗和继续按钮边界，并实际点击。显示胜负、回合、真实伤害/回复和存活统计；自由战斗可再来一局，战役可返回行程；新局/恢复清除旧结果和历史动画 |

## 验证入口

`scripts/check-client.ps1`与`.sh`保留原鼠标、拖牌、存档、布局和G0检查，同时接入公开处理区、完整详情、已有键盘兼容、缩放与首城行程检查。

- `--battle-quality-smoke`：跨友军排序、40张显示夹具的边缘滚动、失焦/右键/Esc取消不改规则哈希、终局查看及开始新局。显示夹具不进入规则核心或存档。
- `--battle-presentation-smoke`：4种窗口 × 4档缩放 × 16种人数，共256组；另查资料/设置/手牌弹层、减少动态、双击与暗牌响应。
- `--battle-inspection-smoke`与`--battle-processing-smoke`：完整说明、灰置牌、滚动边界、转换牌用途、反制对象和恢复。
- `--campaign-smoke <专用目录>`：三条出身在两个窗口尺寸下共六条首城行程，含失败重试、中途活动牌局保存恢复及最终归属恢复。

无头显示服务器将原生弹窗报告为1×1，因此不把无头弹窗几何检查冒充真实窗口验证；终局继续按钮在无头检查中直接触发，在有渲染检查中通过父视口的嵌入弹窗路由注入实际坐标的鼠标事件。

实际画面可用`--battle-preview <绝对PNG路径> 2 2 hover|drag|hand|settings|result|impact`生成；连续出牌使用`cast-animation`。画面和日志写入忽略的build目录，不作为OL来源证据。

## 交付边界

本次可验证的是现有八种牌及技能开发子集的战斗交互和首城工程切片。通用人物仍有文字占位，装备和判定规则、正式OL人物扩充、完整三线内容、全部语音以及同版本视觉验收没有因此完成。Windows开发机程序检查也不代替独立无SDK设备验收。
